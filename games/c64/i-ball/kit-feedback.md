# I-Ball — kit feedback

Written in the retrospective (`kit/skills/core/80-retro`). Which skill text
changed what the run did, what the skills and kit got wrong or left out,
what was changed, what needs a maintainer's decision, what cost the most
time, operating system and tool versions.

## Skill text that changed what I did

- `50-coverage`: "A pace in a comment is a measurement": I counted checkpoints on the four interrupts and on `timer_tick`, found the logic pass skips frames when the screen is busy, and corrected 31 comments that said "frame" where the code counts passes, the level timer among them.
- `60-verify`: "wrong, and every other comment that says the same thing": the sample found two music patterns miscounted; recounting all 34 with the driver's rule corrected 12 more, and two more leftover tables shared the wrong routine name.
- `70-minisite`: "A widget that runs a mechanic is a claim too": the disc widget's test showed a death on a checkpoint's own place takes nothing away, and the keyboard test put the up key's test at `$4946`, not `$4967`; both were wrong on the page before the tests.

## What was changed in the kit

- `kit/c64/INSTALL.md`: behind a re-signing HTTPS proxy, give `cargo install` the proxy and its certificate bundle on the command line (`CARGO_HTTP_PROXY`, `CARGO_HTTP_CAINFO`). Install notes, not a lesson: the failure shows itself.
- `kit/c64/INSTALL.md`: when `apt-get download` fetches nothing, take the `.deb` files from the archive's pool with `curl` and unpack them into `tools/vice-libs` as before. Install notes, not a lesson.

## Candidates

- **Comments a script wrote share one belief.** The music patterns' comments were generated by a script that counted every event as a note. The sample drew two of them and both were wrong; 12 of the other 32 were wrong for the same reason, and the 20 that held did so only because those patterns have no rests. A checker that finds one generated comment wrong should have the whole generator's output rechecked, not just the comment. A skill line in `60-verify` would say: when a wrong comment was written by a script, recount every comment that script wrote. No other game folder shows it yet.

## Maintainer asks

- **Say in START.md that a cloud session must have the contributor's fork attached before it can push.** In this run the session's git proxy refused to push to the contributor's fork (HTTP 403, "not in this session's authorized repository set") for most of the run; the branch could be pushed only once the fork was added to the session, late in the run. `kit/START.md` step 1 could tell a cloud session to attach the fork (or ask the contributor to) when it records the fork's address, so the first push does not fail after hours of work.
- **Let a program file that loads over the KERNAL's vectors be started without the KERNAL.** I_Ball.prg loads at `$0314`, over the IRQ vector, so the KERNAL's own load jumps into the half-loaded file when the next interrupt comes and hangs. The run wrote the file straight into memory with `$01` at `$34` and set the vector last (`orientation.md`). A `kit/c64` helper that injects a program file this way, and a line in the C64 `steps` skill naming the symptom, would save the next game that loads below `$0400` the hour it took here.

## What cost the most time

Pushing: a note in `kit/START.md` telling a cloud session to attach the contributor's fork when it is named would have saved the run's longest wait.

Operating system and tools: Ubuntu 24.04.5 in a Claude cloud container (x86_64); VICE vice-mcp v3.13.2 (release zip, its libraries unpacked into `tools/vice-libs`); regenerator2000 0.9.20 built with cargo; Chromium and Playwright as the container provides them.
