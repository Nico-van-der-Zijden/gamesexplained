The game is a 6502 program in eight parts, loaded from tape as the war needs them: the script that loads and calls the others, the title, the menu, the map, the battle, the fort, the train and the ending. The port is the same program written again in JavaScript, one function for each routine the game calls, 606 in all, reading and writing the game's variables at the game's own addresses, its self-modified operands included. The page runs only the port: the game's code is in the tests, as the original the port is held to.

CheckWhat it showed
Each routine aloneEight test files call 410 of the port's routines and the game's own routine on the kit's 6502 simulator from the same state, made from saved moments of play with sides, levels, sticks, units, fighters and timers changed at random, and compare every byte of memory, the writes to the chips, the registers each leaves and whether it ends its caller's pass as the game's two pla do. Every one agrees in every case: 350,330 cases in all. The rest of the routines are the main loops, the waits and the interrupt handlers, which the next rows hold.
Each part in lockstepThe port's main loops run beside the game's code, pass by pass, from 331 moments saved in three wars the computer played against itself or against a stick moved at random, each until its part ends or for 2,500 frames: the 79 of the map, the 62 battles, the 36 forts, the 19 trains and the 135 of the ending, every one identical. At the start of every pass every byte of memory, colour RAM, the video chip and the sound chip was the same.
The title and the menuFrom the script's call of the title, through the title, the menu's clicks and the year's text to the map, beside the game with every byte the same at each stop: 103,090 passes in the first 6,000 frames.
The page's memoryThe page carries the machine as the script leaves it when it calls the title, and the tapes' fourteen files, with every instruction set to zero but those of the sound drivers, which the port runs on the site's 6502, and the bytes of instructions the game rewrites and reads as its state. The page's machine on that memory and on the whole memory runs the same, frame for frame, from the title into the war.
The paceThe port executes no instructions, so the page charges each stretch of the map's, the battle's, the fort's, the train's and the ending's main loops, and each routine they call, the cycles they cost the game, fitted on 6.1 million stretches timed on the simulator from 137 moments, and each interrupt the average of the game's handler. The map, the title, the menu and the script count their own work, scaled to the game's. Run beside the game for 500 frames from each moment, the page makes the same number of steps of the part's main loop as the game at the median on the map and the ending, and 0.7 % fewer on the train, 2.6 % fewer on the battle and 4.2 % fewer on the fort. A few battles part further: a redraw there waits on a byte the interrupt changes, and once a few cycles move one redraw by a pass, the page and the game draw on different passes from then on.
The listingPorting a routine means reading every instruction of it. The port showed nine of the listing's comments wrong or missing what the code does, and each has been corrected in the Source code tab (port/corrections.md). Five of them come from three bugs in the game, and the port found a fourth, outside the listing's comments; all four are on the Discoveries page.
