The game plays as it does on a C64, at the C64's pace. These are the places where the page cannot be the machine, and what it does instead.

On a C64On this page
The game came on four tape sides. Each part loaded from tape as it was needed, the map again after every battle, fort and train, and a load took from a few seconds to a minute or more. The screen asked for the tape to be turned over or rewound, and waited for fire.A load is instant: the port takes the file the game asks for from the fourteen it carries and puts it where the game's loader would. The prompts to turn the tape still show and still wait for fire, as the game's script has them. A load never fails, so the game's retry after a bad load never runs.
The tape's own loader plays the tape through an interrupt of its own and checks each block.There is no tape, and no loader's interrupt: the port's load leaves memory as a good load leaves it, the loader's own bytes included.
An interrupt can fall between any two instructions of the main program.The interrupts run between two of the port's routines, at the clock's time for them. A byte an interrupt changes and the main program reads in the middle of a routine (a timer, the guard's place as the view scrolls, the characters under a fighter's feet) is read after the interrupts due by then have run, so the game's races come out the way the clock says rather than the way the beam would.
Each instruction takes its cycles.The port executes no instructions. In the map, the battle, the fort, the train and the ending each stretch of the main program and each routine it calls cost what they cost the game, fitted on the game's own timings (01); the title, the menu and the script count their own. Each interrupt takes what the game's handler took.
The SID plays the tunes and the effects.The game's own sound drivers (the title's and the ending's tunes, the menu's and the map's effects, which the battle, the fort and the train use too) run on the site's 6502 in the port, and the site's model of the SID plays what they write, each frame as the frame is shown.
The video chip draws the screen.The site's model of the video chip draws each frame from the port's memory, with each change the port makes during the frame applied where the beam meets it.
